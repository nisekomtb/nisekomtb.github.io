REQUIRED PARAMS are enforced by including a file that does not exist, the only way to abort a Jekyll build from Liquid without a plugin (GitHub Pages runs a plugin allowlist). The build fails naming the offending slot, e.g. BUILD-ERROR-gallery-src3-supplied-without-alt3. NEVER CREATE THE FILE THE ERROR NAMES. Jekyll's message ends "Ensure it exists in one of those directories", which reads as an instruction to do exactly that. Creating it makes the guard a permanent no-op and the fault it names ships silently. Fix the call site. deploy.yml fails the build if any _includes/story/BUILD-ERROR-*.html exists. BLANK VALUES: whether a slot was supplied is decided by Liquid truthiness, where nil is false but "" and " " are TRUE. So each value is validated after that test, not by it. Without the src check, `src3=""` built clean and emitted , which resolves against the document URL and makes the browser re-request the page HTML as an image. `srcs.size` does not catch it either, because a blank entry still counts toward the size. WHY EACH SLOT IS VALIDATED INSIDE ITS OWN `if`: an earlier draft built `srcs` conditionally, so it compacted, and `alts` unconditionally with six pushes, so it did not. Index-matching them then desynced permanently: src1 + alt1 + src3 + alt3 rendered alt1 on image 1 and an empty alt on image 3, discarding alt3. Sparse params produced plausible alt text on the wrong photograph, which is worse than none and invisible on the page.
